# ROOT REBIRTH・ROOT結晶と恒久強化

## 現行仕様（#47 / v17）

新たにROOTを確定したときだけ、現ROOTの通常転生回数、未使用pt、通常スキル5種の全ランク、下位の突破・解析権、現ROOTの解析完了を0/falseへ戻します。周回SCORE・芋・設備・研究・端数・再購入制限も初期化し、上限は1e6です。今回の未使用ptと全取得スキルの累積費用を `pointsLostByRoot` に加算し、返還しません。通常転生報酬は付与しません。

生涯通常転生回数 `lifetimePrestigeCount`、累計獲得pt、消失台帳、累計解析回数と深層記憶、発見履歴、ROOT結晶・強化、装備・モード・プリセット、DEPTH・掘削研究を保持します。設備や研究の発見済み名称は残り、現ROOTで権利を取り直すまでは利用できません。初期芋は保持したROOT強化だけから計算します。

初回ROOTで `rootAutomationUnlocked` を恒久取得します。自動購入は「自動購入スキルあり、またはROOT恒久権あり」で利用可能です。ON/OFF・対象・順序・方策を保持し、スキル0でも設定どおり動きます。心得は新たに通常転生5回と前提スキル・費用を満たして再取得します。通常転生は現ROOT回数と生涯回数を両方増やします。

ROOT回数による全収穫倍率は **1＋2×ROOT回数**（0/1/2/3回で1/3/5/7倍）。既存のROOT強化・装備効果はそれぞれ一度だけ乗算します。高いROOT回数の倍率も巨大数で計算します。

v1〜v16の移行は資産・スキル・ポイント・権利をその場でリセットしません。旧通常転生回数を生涯回数へコピーし、ROOT済みなら自動購入恒久権と `legacyRootProgress` を補完します。旧保存の現ROOT解析完了の推定はv15の方式を継続し、判別できない段階0の履歴から新しい解析完了を捏造しません。旧版から保持した権利・高ランクは移行互換として許可し、次の明示的ROOTで互換フラグを解除します。v17以降の新しいROOTは現ROOT段階だけで権利・ランクを検証します。

ポイントは `累計獲得＝取得スキル費用＋未使用＋解析消失＋ROOT消失` を厳密照合し、履歴の上限は生涯通常転生回数を使います。ROOT前の確認画面に今回失うptと対象を表示し、保存成功後にだけ状態を公開します。取消・容量不足・競合ではリセットと結晶受領を確定しません。

シミュレーターもROOT後の通常転生を省略せず、上限1e6の実周回で10ptを集め、収穫3・割引1・心得を買い直します。1分・6h・12hの手動/自動、結晶の代表選択、装備を伴う3回の再ROOTを既存の経路比較で校正します。最新の時間は [生成レポート](balance/generated/report.md) を参照してください。

| 確認間隔 | 手動購入・ROOT後→次ROOT | 自動購入・ROOT後→次ROOT |
| --- | ---: | ---: |
| 1分 | 15時間22分 | 4時間45分 |
| 6時間 | 120時間 | 66時間 |
| 12時間 | 204時間 | 120時間 |

原初の恵み1を選ぶ代表経路です。1分自動の再育成は11分、6時間自動は36時間、12時間自動は72時間を含みます。全8経路と装備・構成の3回再ROOTが90日以内に完走し、初回ROOTまでの各経路より短いため、この倍率を採用します。低頻度の確認は通常転生5回を含む各復帰待ちの影響が残ります。回数倍率だけで全短縮を説明する比較ではありません。

以下は#32時点の仕様と校正記録です。リセット・保持・倍率・ポイントについては上記を優先します。

#46 / v16: [現行の報酬・ランク上限・ポイント非返還・台帳](prestige-economy.md)。以下の旧仕様・校正記録より現行ルールを優先します。

現周回の累計SCORE 1e18で、任意・手動の根源転生を選べます。現在の報酬は初回も再ROOTも結晶1個です。報酬段階は `data/root.ts` に分離し、1e21以降の報酬や上限は先行実装しません。通常転生（2pt）も選べます。

## リセット・保持と受領

| 対象 | ROOT後 |
| --- | --- |
| 現周回SCORE・所持芋・設備・上限段階 | 段階0・設備0・SCORE0へリセット |
| 現ROOT内の深層解析完了・引継ぎ開始段階 | false・0へリセット。通常ポイント・スキルは消去しない |
| 周回研究4種・生産端数・当周回の強化スキル再購入制限 | リセット |
| 通常転生回数・通常ポイント・取得スキル | 保持。通常転生を同時実行せず、通常報酬を付与しない |
| 全突破/解析権・発見履歴・自動購入の解禁と全設定 | 保持 |
| DEPTH・深度端数・地層発見・恒久掘削研究 | 保持 |
| ROOT回数・結晶・恒久強化・装備システム解禁権 | 保持し、今回のROOT報酬を加算 |

初期所持芋は維持した通常スキルとROOT強化から計算し、`runStartingImo` へ記録します。SCOREには加算しません。ROOT後のSCOREは0なので、連続実行では報酬を再受領できません。放置精算でもROOT・突破・研究購入は自動実行しません。

操作直前に旧倍率で経過時間を精算します。確認の取消は状態を変更せず、確定時も保存成功後にだけリセットを公開します。容量不足・他タブ競合・旧版移行失敗では元セーブを保護します。

## 初回ボーナスと結晶の選択

初めてROOTすると全収穫×3を恒久取得します。回数ごとに×3を掛ける仕様ではありません。初回ROOTの結晶1個でも次の2種類から選べ、温存もできます。

| 恒久強化 | ランク別結晶費用 | 効果 | 前提 |
| --- | --- | --- | --- |
| 原初の恵み | 1 / 2 / 3 | 全収穫×1.5 / 2.25 / 3.375 | 初回ROOT |
| 根源の記憶 | 1 / 2 / 3 | 設備割引10 / 15 / 20%、次回初期芋+100 / 250 / 500 | 初回ROOT |
| 地底への適応 | 1 / 2 / 3 | 地脈抽出機以降の設備収穫と全掘削力×1.5 / 2.25 / 3.375 | 原初の恵み1 |

全収穫は基礎・設備・リンクへ適用します。後期強化は設備の解禁上限1e12以上を対象とし、リンク追加収穫は含めません。通常収穫スキル・周回研究・設備台数倍率との乗算です。設備割引は通常割引と乗算し、各台の価格を最後に切り上げます。掘削倍率はSCORE稼働区間だけ適用します。

記憶の設備割引は購入直後から、初期芋は次の通常転生/ROOTから適用します。購入時に初期支給を遡って受け取る処理はありません。振り直しはなく、購入前に用途と適用時期を案内します。根源の記憶は序盤支援と価格低下、原初の恵みは長い収穫待ちの短縮という違いがあります。

ROOT結晶はSCORE・所持芋・通常ポイントから購入できません。通常ポイントと別の元帳で消費し、不足・最大ランク・前提不足は無変更です。費用・段階効果・前提をデータ定義にし、将来の上位スキルへ拡張できます。[恒久装備](gear.md)は利用可能SCOREで解禁し、ROOT後も保持します。[効果モード・プリセット](gear-modes.md)も保持します。

## 再周回で深層解析を永久ロックしない

従来の `deepResearchCount <= prestigeCount - 4` だけでは、通常転生を挟まないROOT再周回で解析回数の上限に達します。ROOTも周回を終了するため、現在は `deepResearchCount - rootRebirthCount <= max(0, prestigeCount - 4)` とします。安全整数を足してオーバーフローしないよう差で検証します。

ROOT履歴には解析履歴が必要で `rootRebirthCount <= deepResearchCount`、段階2以上の現ROOT周回では新しい深層解析が必要なので `deepResearchCount > rootRebirthCount` を要求します。ROOTで通常回数/ポイントを増やして辻褄を合わせる処理はありません。深層記憶の2/3/4回目の保持枠は累計のまま進み、通常の解析によるリセット/返還も維持します。

## 表示と保存v12

第4突破の発見後にROOT条件・報酬・リセット/保持範囲を表示します。初回ROOT前は具体的なROOT強化の名前/価格/効果や装備一覧をDOMへ出しません。初めてROOTを実行すると小さな線画演出と装備システム解禁の案内を表示し、以後の転生でも隠し直しません。装備5種の予告・購入・計算は追加しません。線画は動きを減らす設定に対応します。

v12で恒久状態へ次を追加します。

```ts
rootRebirthCount: number;
unspentRootCrystals: number;
totalRootCrystalsEarned: number;
totalRootCrystalsSpent: number;
rootUpgradeRanks: { blessing: number; memory: number; adaptation: number };
equipmentSystemUnlocked: boolean;
```

全カウンターを非負安全整数として検証し、現報酬1個では `earned == rootCount`、`spent == earned - balance`、`spent == 各取得ランク費用の総和` を要求します。解禁フラグはROOT回数が正の場合だけtrue、取得ランクは上限/前提/解禁を満たす必要があります。ROOT履歴と最大発見段階4・解析履歴も照合します。

v1〜v11は既存資産・通常ポイント・深層記憶・DEPTH・研究・自動設定・日時を保持し、ROOT回数/結晶/強化0・装備未解禁を補完します。昔の1e18到達だけで結晶やROOT済み権限を付与しません。エクスポート/インポートは全ROOT状態を保存します。[保存仕様](save.md)を参照してください。

## 初回と2回目の実ルート

初期状態から実際に1e18へ到達した#31の6経路を使い、ROOT・最初の結晶購入・維持した通常ポイントでの収穫3/割引1再取得を実行します。追加の通常転生を挟まず、段階0〜4を再突破して2回目のROOTまで測定します。研究・突破・ROOTは確認時だけ手動です。

| 確認 | 購入 | 初期→初回ROOT | ROOT後→2回目 | そのうち序盤1e6まで |
| --- | --- | ---: | ---: | ---: |
| 1分 | 手動 | 184h1m | 15h1m | 4分 |
| 1分 | 自動効率 | 49h23m | 4h35m | 1分 |
| 6h | 手動 | 156h | 60h | 12h |
| 6h | 自動効率 | 126h | 36h | 6h |
| 12h | 手動 | 276h | 84h | 24h |
| 12h | 自動効率 | 192h | 60h | 12h |

表は原初の恵みを1取得した主経路です。固定×3と結晶選択で明確に短縮するため、初回×3案を採用しました。序盤でも設備購入を経て実際に稼ぎ、上限や設備を自動でスキップしません。低頻度確認では各上限後の待機時間が残ります。初回と2回目は保持スキル・深層記憶の履歴も異なるため、短縮全体を固定×3だけの効果と解釈しません。

結晶の比較は1分/6h自動の2件だけ追加します。1分自動では原初の恵み4h35m、根源の記憶6h35mで、序盤1e6は1分/2分です。6h自動では両方36hですが、上限到達実時刻と待機時間が異なります。根源の記憶の追加100芋は2回目のROOT直後に支給され、最初のROOT直後に支給した扱いにはしません。

主6件＋選択比較2件の8経路が再ROOTまで完了し、全件で通常転生回数は初回ROOT前と一致、ROOT回数2・累計結晶2・使用1・残高1となります。全強化ランク×全方策の行列は作りません。[比較CSV](balance/generated/root-cycle.csv)・[段階別時系列](balance/generated/root-cycle-timeline.csv)・[選択比較図](balance/generated/root-cycle.svg)・[生成レポート](balance/generated/report.md)を参照してください。

## 精度・負荷と重点検証

最大の通常割引20%×ROOT割引20%、予算1e18＋最大初期支給600芋での保守的な独立購入台数は284/205/157/151/127/129/95/51/35/34/17、合計1285台です。既存の2048購入・16384イベント上限内で、超過/非進捗時の原子的停止を維持します。

Node24/Windowsで正規自動3経路の5段階開始状態を24h精算した45件は中央値約2.7ms、p95約9.2ms、最大約9.7ms、最大202購入でした。環境依存の参考値です。

ROOT経路の生成物比較は#31と同じ巨大数/端数の許容幅を再利用します。台数・ランク・通常/ROOT回数・結晶元帳・スキーマ・モデルハッシュと旧経路は厳密一致です。ゲームの購入条件や保存検証へ比較用許容幅を入れません。

重点テストは二重受領防止・通常転生との保持/リセット差・4回のROOTによる再解析・結晶元帳/効果・代表オフライン/復帰・v11移行の4件、表示フロー1件、既存の保存失敗テストへROOT/強化の2ケース追加です。既存シミュレーターの回帰検証を再利用します。
