# 第4限界突破・根源領域（#31）

段階3で現周回のSCORE 1e15へ到達すると、手動・無料の「地底核心の解析」で `scoreCapStage=4`、上限GameNumber 1e18へ進みます。SCORE・所持芋・設備・周回/恒久研究・DEPTH/端数・スキル・ポイント・自動設定を保持し、生産と掘削を再開します。研究やDEPTHの到達条件はありません。

`permanent.originAnalysisUnlocked` と最大発見段階4は通常転生でも保持します。通常転生は従来の2ptで、段階0・設備0・周回研究0へ戻し、各上限へ再到達すると無料で再突破できます。深層記憶の保持・ロックは第2突破で従来どおり処理し、第3/4突破では変更しません。最大発見段階を下げないため、再周回中も発見済み設備・研究の名前を保持します。

1e18では生産・設備/研究購入・掘削を停止し、「ROOT REBIRTH準備完了（次Issueで実装）」を表示します。通常転生は選べます。ROOT通貨・ROOT転生・ROOT設備・新たなリセット操作は#32/#33で扱います。

リンク研究は新設備へ一律に倍率を掛けるものではありません。連携直前の中継塔/培養槽にも価値があり、低成長率の根源採掘機と高単価の芋核炉へ貯める判断と競合します。6h自動・研究ありの終点はリンク11組・採掘機12台・芋核炉9台、6h手動では11組・9台・5台です。どちらか1設備だけを常に買う経路にはなっていません。1分手動の「買える物を毎回購入」では芋核炉へ貯めず、到達が遅くなります。最適方策の保証ではありません。

## 発見と保存

第4突破前は新設備/研究の名前・価格・効果・自動設定のIDをDOMへ出さず、第3段階以降に次の突破条件と任意の「？？？」を表示します。実際の解析成功後に設備2種と研究2種を公開し、通常転生後も名前を保持して当周回の未解禁理由を表示します。ROOTの準備表示は実際の1e18到達時だけ出します。

保存v11はv1〜v10の資産・履歴・DEPTH・時刻・全体自動設定を保持し、新設備0・新研究0・解析権falseを追加します。旧5/7/9設備のフラグ・順列を検証後、新IDをON・順列末尾へ追加します。無権限の段階4・段階3以下の新設備/新研究・不正ランク・残高超過を拒否します。解析・研究も書込成功後にだけ反映し、容量不足/競合/移行失敗では元データを保護します。形式の詳細は[保存仕様](save.md)。

## 精度と処理量

金額の比較・支払可否・上限クリップはGameNumberで行い、購入条件へ許容誤差を加えません。1e18は単位精度を保証する範囲ではないため、単台/MAXや分割精算の比較は金額の絶対1芋または相対1e-12以内、台数・ランク・上限SCOREは厳密一致です。DEPTHの数値境界は従来どおりです。

根源領域のJSON/CSVは秒数・深度などの非整数numberの比較表示を12有効桁へ揃えます。巨大数は成分を省略しない正規gn1文字列を維持します。ゲーム計算・購入可否・セーブ/エクスポートには表示用の丸めを適用しません。

自動購入直後の微小残高や補償端数には、その直前の巨大な支払い/累計に由来する環境差が残ります。`simulate:check` は根源領域の金額を絶対1芋または相対1e-12、残高/生産端数を累計SCORE×64EPS以内、深度を絶対1e-6mまたは相対1e-12、深度端数をmax(1e-9m, 深度×64EPS)、時刻を絶対1e-6秒または相対1e-12で比較します。台数・ランク・方策・スキーマは厳密一致です。根源領域以外の結果とコアモデルのハッシュは厳密一致のままで、パラメーター変更による生成物の更新漏れを許可しません。

最大割引20%・予算1e18＋支給100で、各設備を独立に次価格まで数えた保守的上限は282/204/156/149/126/128/94/50/34/33/16、合計1272台です。1024を超えるため上限を2048購入・16384内部イベントへ変更しました。MAX見積もり50000と非進捗/超過時の原子的停止は維持します。

Node24/Windowsで正規6h自動経路の段階4開始状態を3方針×5回、24h精算した15件は中央値約3.5ms・p95/最大約37.1ms、最大577購入でした。環境依存の参考値です。
