# 初回SCORE限界突破（#20）

転生スキルで恒久的な突破権を取得し、SCORE1e6到達時に**転生せず現在の周回を続けて上限1e9へ進む**機能です。1e9で生産・購入を停止した後は、#24の [地層研究](research.md) で1e12へ進めます。上位転生・装備・1e12より先の突破は未実装です。

以下の時間は #20 の自動購入OFFの取得経路です。#23の [自動設備管理](automation.md) は任意スキルとして別の経路・比較を追加し、この従来経路も維持します。現在の保存はv6で、v4/v5の突破状態はそのまま移行します。

## 権利取得と周回の上限

| 対象 | 保存先 | 条件・効果 |
| --- | --- | --- |
| 限界突破の心得 | `permanent.skillRanks.breakthrough`（0 / 1） | 収穫ランク3・割引ランク1・累計転生5回以上、3ptで取得 |
| 現周回の上限段階 | `scoreCapStage`（0 / 1 / 2） | 0: 1e6、1: 1e9、2: 1e12（地層研究） |
| 突破実行 | `canBreakthrough` / `performBreakthrough` | 権利取得済み、段階0、SCORE1e6で実行可能。追加pt不要 |

権利の取得だけでは上限を上げません。採掘欄の「限界突破する」から確認して実行します。操作直後は、上限段階だけが変わり、SCORE・所持芋・所有設備・開始支給額・スキル・転生回数・残ポイントを保持します。SCOREの付与はありません。止まっていた生産が再開し、深層掘削機・芋精製プラントが購入可能になります。

通常転生はSCORE10万で1pt、100万以上で2ptです。突破後も2ptのままで、上位転生の報酬は先行実装しません。転生すると設備・SCOREをリセットし、周回上限は1e6へ戻ります。取得済みの心得を保持し、再び1e6に到達したときは追加ポイントなしで再突破できます。

周回上限を初期値に戻す方式を採用した理由は、通常転生の既存ループ・初期設備の成長を維持しながら、恒久権利のための再課金をなくすためです。突破後にもう一度転生する必要はありません。実経路でも権利取得後の次周回を継続して1e9に到達しています。

## 採用条件と経路の検証

前提スキルは収穫3で6pt・割引1で1pt、心得で3pt、合計10ptです。上限転生なら5回分、早期転生なら10回分になります。回数だけを短期周回で増やしても前提・ポイントを満たせません。心得の3ptと転生5回条件を採用し、既存の設備価格・台数倍率・基本3スキルは維持しています。

現在の `npm run simulate` は初期状態から実際の購入・転生・スキル取得・突破・現行v6保存を通し、次の経路を測定します。操作判断の所要時間は0で、人が迷う時間や通信遅延は含めません。この5経路は自動購入OFFで、最適経路の証明ではありません。

| 方策 | 最初の1e6 | 権利取得 | 突破時点 | 突破後1e9まで | 開始から1e9まで |
| --- | ---: | ---: | --- | ---: | ---: |
| 1分確認・突破優先 | 12分 | 43分 | 50分、5回転生・10pt獲得 | 3時間40分 | 4時間30分 |
| 6時間復帰・突破優先 | 12時間 | 2.5日 | 3日、5回転生・10pt獲得 | 12時間 | 3.5日 |
| 12時間復帰・突破優先 | 24時間 | 5日 | 6日、5回転生・10pt獲得 | 24時間 | 7日 |
| 1分確認・早期転生から | 51分 | 44分 | 51分、10回転生・10pt獲得 | 3時間40分 | 4時間31分 |
| 1分確認・既存スキル買切り後 | 12分 | 60分 | 65分、8回転生・16pt獲得 | 3時間17分 | 4時間22分 |

早期方策の最初の1e6は、権利取得後に早期転生をやめて上限へ進んだ時刻です。既存スキルを先に買い切る経路は15pt支出・1pt残で突破し、総時間は突破優先より短くなりました。優先経路が常に最速とは主張しません。別スキルへの投資でもポイントは通常転生で引き続き得られ、永久ロックは生じません。既存15方策の初回・6周の時間は #19 と一致しています。

### 設備購入による加速

1分確認・突破優先の実際の突破直前状態を比較元にします。SCORE1e6、所持7,984、既存設備48/33/24台、スキル収穫3・割引1・開始芋0・心得1、転生5回・残0pt、生産7,797.925/秒です。この同じ状態に正規の突破を適用した後、購入方策だけを変えます。

| 確認間隔 | 購入なし | 既存3種のみ | 追加2種を含む5種 |
| --- | ---: | ---: | ---: |
| 1分 | 35時間36分 | 15時間43分 | 3時間40分 |
| 6時間復帰 | 36時間 | 18時間 | 12時間 |
| 12時間復帰 | 36時間 | 24時間 | 24時間 |

1分確認の5種購入では深層掘削機17・プラント6台、到達生産307,170.109375/秒となり、開始生産から約39.39倍、既存3種の到達生産に対して約13.28倍です。価格と生産量は #19 を維持しました。#4 の固定生産39.77時間や #19 の仮定3.28時間とは開始状態・権利取得費用が違うため、同じ試算として混同しません。

低頻度では復帰時だけ購入します。6時間・12時間の正規経路は突破後に各2回の復帰で1e9へ到達し、上限到達後の停止待ちは約4.98時間・11.43時間です。設備による加速は確認できますが、確認待ちの長さは残ります。各購入時点の台数・生産力と上限を [時系列CSV](balance/generated/breakthrough-timeline.csv)、比較用の9ケースを [設備比較CSV](balance/generated/expansion.csv) に記録しています。

## コア・保存・UIの境界

`src/data/scoreCaps.ts` の段階表と `getScoreCap(state)` を、進行・購入停止・設備解禁・UIゲージ・保存・オフライン計算で共有します。`EconomyContext` による仮の上限上書きは削除しました。段階1には心得と前段階の到達SCOREが必要で、不正段階・権利不足・上限超過・初期段階での上位設備所有を拒否します。

`performBreakthrough` は不成立や二重実行で入力状態を返します。セッションは操作直前に時間と他タブを確認し、候補の保存に成功してから段階を反映します。容量不足・権限エラー・競合では現在の段階を維持して停止します。確認UIは取消・Escape・フォーカス復帰に対応し、初期上限では通常転生と突破を別操作で選べます。

#20で保存v4、自動購入でv5、地層研究でv6を導入しました。v1〜v3は既存値を保持し、段階0・心得0を補完します。v1は恒久データ未取得、v1/v2は欠けた上位設備だけ0で補完します。v3〜v5は旧5設備、v6は全7設備が必須です。旧形式に研究0・新設備0・研究権限falseを補います。通常の24時間放置制限、入出力確認・追加放置報酬なしのインポート、破損保護・複数タブ検知を維持します。[保存仕様](save.md) を参照してください。

`npm run typecheck` / `npm test` / `npm run build` を実行します。テストは上限直前・直後・小数・極端な長時間、未取得・条件不足・二重実行、非リセットの保持範囲、転生後の無料再突破、旧形式移行とv4復元、放置クリップ、確認取消・保存失敗・競合を検証します。

`npm run simulate` / `npm run simulate:check` は既存15方策・正規突破5経路・設備比較9ケースを再計算し、自動購入・研究比較を含む21成果物の一致を確認します。初期帯・突破経路・固定生産の将来感度分析を区別します。[生成レポート](balance/generated/report.md)・[経路CSV](balance/generated/breakthrough.csv)・[上限付き成長図](balance/generated/breakthrough.svg) を参照してください。
