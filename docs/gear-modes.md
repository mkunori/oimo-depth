# 装備の効果モード・プリセット

#46 / v16: [現行の報酬・ランク上限・ポイント非返還・台帳](prestige-economy.md)。以下の旧仕様・校正記録より現行ルールを優先します。

Issue #34。#33のROOT条件、SCORE価格、常時効果は変更しない。全解禁装備は常時有効で、各装備の追加モードを1つ選ぶ。切替は無料・即時。標準モードは追加効果なしで、旧保存・新規解禁は必ず標準から始める。標準だけでも従来と同じ放置進行が可能。

## データと計算

倍率・モードIDは `src/data/gearModes.ts` の `GEAR_MODES` を正とする。装備パッシブの `gear` と追加モードの `gear-mode` は別の効果源。

| 区分 | 設備ID |
| --- | --- |
| 初期3 | worker / cart / harvester |
| 初期5 | 初期3 + deepDrill / refinery |
| 深層以降 | veinExtractor / concentrator / rootRelay / coreChamber / originMiner / imoReactor |
| 採掘系 | deepDrill / veinExtractor / rootRelay / originMiner |
| 精製系 | refinery / concentrator / coreChamber / imoReactor |
| 根脈設備 | rootRelay / coreChamber |

適用順序:

1. 各設備の台数・節目・研究・ROOT後期倍率に、その設備対象のモード倍率を掛ける。
2. 基礎生産、設備生産、リンク追加生産を合計。リンク追加生産にはリンク用モード倍率だけを掛け、設備対象倍率を流用しない。
3. 合計に既存の全生産倍率、全解禁装備の常時倍率、モードの全生産倍率をそれぞれ1回掛ける。
4. 掘削力は既存式に掘削モード倍率を掛け、実効硬度（地層の硬度×地質適応倍率）で割る。芋の生産・購入価格・結晶報酬には影響しない。

根脈集中は根脈2設備それぞれとリンク追加分それぞれに×2.2。リンク追加分に設備倍率を重ねない。コンパスの設備連携×2との組合せではリンク追加分×4.4。研究共鳴は地質研究1以上のときだけ発動し、地層の到達履歴とは別に判定する。対象設備やリンクがない効果は休眠し、通常の常時効果を保持する。

自動購入の収穫効率優先は変更設備とリンクの実生産差から判定する。巨大な不変の生産を先に相殺しない。生産・購入候補キャッシュにもモード構成を含める。

## プリセットと操作

標準に加え、高速周回・長期成長・根脈連携・DEPTH探索の4構成。所有装備だけを一括変更し、未解禁装備には予約を残さない。新規解禁の標準モードが選択中の構成から外れる場合、表示をカスタムにする。個別変更も選択プリセットとの一致を再判定する。

カスタムは3枠。保存は所有装備だけのスナップショットとし、その枠を選択する。既存枠への保存は上書き。名前変更は構成を変更しない。名前は前後空白を除く1〜20文字、制御文字と他枠・組込名との重複を拒否。削除は現在のモードを変更せず、選択中の削除枠はカスタム表示にする。保存後に増えた装備は標準で復元する。

折り畳み内でモード候補、発動条件、切替前後の収穫・掘削・実効硬度を表示する。組込プリセットは比較値を見てボタン1回で適用可能。未知・未所有装備のモードやIDはDOMに出さない。

`getGearModeEffects` は全体・設備・リンク・掘削力・硬度の実倍率、`previewGearChange` は変更前後の実収穫速度・掘削速度・実効硬度を返す。上限中の実速度は両方0。

## 時刻・保存

GameSessionは切替操作の時刻まで旧構成で収穫・自動購入・地層跨ぎを精算する。その状態に変更を適用し、保存に成功してから公開する。保存失敗時は変更を公開せず、元の保存を保持する。外部タブの変更を検出したら切替を拒否する。上限中の切替で収穫・掘削を再開しない。

セーブv14。v1〜13は標準モード、空の3枠、標準選択を補完する。モードは装備ごとにIDを検証し、未所有の非標準モード、未知ID、選択と構成の不一致、不正な枠・名前・保存対象を拒否する。移行書込み失敗では元のテキストをエクスポート可能。全設定は恒久データに属し、通常転生・ROOT後も保持する。

## 比較・許容誤差

`npm run simulate` は初回ROOTへの実経路を共有し、1分自動・6時間自動・12時間手動×4プリセットの12経路でROOT1〜3の36周回を計算する。各訪問時に装備解禁を試し、その後に明示的にプリセットを適用。解禁時点の標準開始と、後続の切替は別イベント。比較CSVに周回時間・SCORE・DEPTH・解禁順・実モードを記録し、時系列CSVに切替・収穫・掘削を記録する。

1分自動のROOT3では高速周回2h41m、長期成長1h27m、根脈連携1h25m、DEPTH探索3h16m。高速周回は序盤1E6まで1分、他3構成は2分で、深層以降を含む全段階の最速を意味しない。DEPTH探索はROOT3終了で約112,694m、長期成長は約101,115m。6時間自動では多くの構成が各30h、12時間手動では各84hに丸められる。4構成とも解禁数は3→4→5、価格・常時倍率は据え置く。旧mainの88,902項目は標準モードで一致。結果は [生成レポート](balance/generated/report.md) を参照。

同じ時刻に切り替えたオンライン分割とオフライン精算を重点テストする。台数・ID・モード・レシートは厳密一致。SCOREは絶対誤差1e-6または相対1e-12、DEPTHは1e-6mをテスト許容とする。生成レポートのプラットフォーム間比較は従来どおり金額の絶対1または相対1e-12、残高の桁落ちは累計SCORE×64EPS、深度は1e-6mまたは相対1e-12。保存・購入判定には許容誤差を使わない。

既存経路の決定性テストは従来マトリクスを2回実行する。新12経路は同じ本番コアを使う生成結果と `simulate:check` の再生成比較で確認し、単体テストで全モード×全設備の組合せを増やさない。
