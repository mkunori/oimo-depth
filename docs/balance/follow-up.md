## 設備拡張 Issue に含める候補

1. 初期帯の13分を維持して転生導入を早くするのか、数時間へ伸ばすのかを決める。両立しない体験目標を先に整理する。
2. 次の桁に必要な生産能力を予算化する。第6周の参照能力6,977.5/秒で固定すると、1e6→1e9は約39.77時間。6時間で届かせるには46,250/秒（参照比約6.63倍）が必要。
3. 新設備・既存設備のマイルストーン・研究のいずれで伸ばすかを定義する。上の6.63倍は固定能力の比較であり、既存設備の追加購入でどこまで伸びるかも実装後に再計測する。
4. 6時間/12時間の確認方策でも、解禁直後に新しい購入が成立し、その次の復帰で効果が見える価格・条件を用意する。自動購入を加える場合はオンラインとオフラインの同一購入ルールを別途確定する。
5. 受け入れ条件に、同じシミュレーターで初周・次桁・1日2〜4回の3群を再計測し、購入不可による停止や数値の非有限化がないことを含める。

新設備の価格/生産量を一意に逆算できるほどの仕様はまだありません。候補値を追加してから実際の購入・解禁を含む曲線で検証する段階が必要です。

## 限界突破 Issue に含める候補

1. #3 のとおり、SCORE・所持芋・設備を保ち、転生せず同じ周回の上限を1e6→1e9へ拡張する。転生は残す。
2. 解禁の回数・必須スキル・ポイント費用を明示する。現行の収穫優先では5回転生後も未使用0ptで、全スキル完了後は次の上限転生で2ptずつ貯められる。既存スキル取得と突破権の必要ptが競合するなら、到達に何周増えるかをシナリオに含める。
3. ポイントを温存すれば1分確認5回で65分・10pt、早期5回では24分・累計5ptとなる。回数・ポイント・スキル条件のどれを用いるかで最短経路が変わる。誤振りによる恒久的な行き止まりを避ける。
4. 1e9へ上限だけ拡張して終わりにせず、設備拡張 Issue と生産予算を合わせる。1e9→1e12を同じ6時間で進めるには46,250,000/秒が必要で、同じ小倍率の繰り返しだけでは足りない。
5. ゲーム状態・保存バージョン・上限判定・オフライン精算・表示の変更を一体で扱う。通常転生で新上限を保持するか、再到達時に再突破するかは仕様決定が必要。
6. 受け入れ条件に非リセット遷移、上限付近の大量時間精算、突破/転生の選択、旧セーブ保護を含める。1e12/1e15は初回突破の評価から分け、number 精度と巨大数対応の境界を確認する。
